# EDA — tableau_cohort_analysis (когортное удержание и LTV)

> [!summary]
> Синтетический когортный лог: 5 469 строк «пользователь × месяц», 1 000 пользователей,
> 10 когорт прихода (2023-01 … 2023-10). Данные чистые (0 пропусков, 0 дубликатов, контракт
> соблюдён), генератор детерминирован (`seed=42` воспроизводит CSV побитово), удержание
> следует заложенной формуле `0.85 · 0.75^(p-1)`. Единственное расхождение с README —
> **число тестов: заявлено 34, фактически 39**.

## Executive Summary

- **Датасет:** `cohort_data.csv` — 5 469 строк × 6 колонок; период прихода 2023-01 … 2023-10; горизонт наблюдения 0 … 9 периодов (треугольная матрица).
- **Grain:** одна строка = один **пользователь × месяц наблюдения** (`user_id` × `period`).
- **Целевые метрики:** `is_active` (retention, доля активных) и `revenue` (выручка user-month). Выручка: 43.7 % строк = 0 (неактивные месяцы); среди активных — mean 9.97, median 10.
- **Главный «разрыв» по `cohort_month` (×2.56) — артефакт состава, а не качества когорт:** старые когорты наблюдались дольше (10 периодов, удержание низкое), младшие — только period 0 (100 %). Это треугольное окно наблюдения, а не разница в поведении.
- **Состояние данных:** чисто — контракт из 6 колонок соблюдён полностью (10/10 проверок валидности PASS).
- **Главный вывод:** пайплайн воспроизводит заложенную модель удержания/выручки без сбоев; расхождение README по тестам — документационное, не в данных.

## Распределения

- **`revenue`** (все строки): скошенность 0.28 — распределение **бимодальное по построению**: пик в 0 (неактивные месяцы, 43.7 %) + сдвиг Пуассона при активных. Медиана 6, mean 5.62. Среднее по смешанной популяции вводит в заблуждение — корректная метрика центра для активных: **median = 10, mean = 9.97** (совпадает с λ = 10).

- **`is_active`**: 0/1, доля активных 56.3 % (смещена к 1 из-за period 0 = 100 %).
- **`period`**: 0 … 9, скошенность 0.59 — убывающие размеры (треугольник), не сбой.
- **`user_id`**: равномерный (псевдо-идентификатор), скошенность 0.02.

## Динамика и аномалии

Настоящей временной оси (событий по дням) в датасете нет: `join_date` — всегда 1-е число месяца,
поэтому недельная агрегация профилировщика по `join_date` даёт «зубья» (нули в не-первых неделях) и
флагует ложную аномалию `-100 %` в 2023-08-13. Это **артефакт оси**, не сбой данных.

Корректная «динамика» здесь — **поток (размер когорт по месяцам прихода)** и **поведение (retention/выручка по периодам)**:

- **Поток:** размеры когорт 77 … 116, mean 100, max/min = 1.51 — приток однородный, всплесков/провалов нет (fig 2).
- **Поведение (удержание):** blended-кривая убывает 100 % → 9.3 % и совпадает с формулой `0.85 · 0.75^(p-1)` (max |Δ| = 0.0149; fig 3).
- **Поведение (выручка):** средняя выручка на активный user-month **плоская по тенуре** (≈ 10 на всех периодах, fig 6) — монетизация не дрейфует с возрастом.

**Аномалий в данных не найдено.** Последний период (2023-10) неполный по построению — читать как падение нельзя.

## Findings (E / H / R)

### Finding 1: Генератор детерминирован — `seed=42` воспроизводит CSV побитово

**Evidence:**
- `cohort_analysis.generate_data(DataConfig(seed=42))` даёт ровно 5 469 × 6 строк, `DataFrame.equals(df) == True`.
- Валидность контракта: 10/10 проверок PASS; period 0 = 100 % (1.0).

**Hypothesis:**
- H1: README-claim «синтетика, seed=42, воспроизводится из кода» верен — данные и код согласованы.
- H2 (альтернативная): CSV мог быть отредактирован вручную после генерации. Опровергнута — побитовое совпадение.

**Recommendation:**
- Действие: закрепить заявление «CSV воспроизводится `seed=42`» как воспроизведённое; в CI сравнивать `generate_data()` с ожидаемым хэшем.
- Рычаг: `time_to_convert ↓` (доверие к воспроизводимости).
- Сценарий проверки: уже выполнен (regen == CSV).
- Приоритет: L

### Finding 2: Удержание следует заложенной формуле — модель корректна

**Evidence:**
- Blended-кривая: 0.845, 0.623, 0.470, 0.359, 0.265, 0.200, 0.154, 0.099, 0.093 против теории 0.850, 0.638, 0.478, 0.359, 0.269, 0.202, 0.151, 0.114, 0.085; max |Δ| = **0.0149**.
- Log-linear fit `ln(retention) = a + b·(p−1)`: base = 0.8357 (теория 0.85), decay = 0.7509 (теория 0.75), **R² = 0.9945**.

**Hypothesis:**
- H1: README-claim `retention(p) = 0.85 · 0.75^(p-1)` подтверждён данными (сэмплинг-шум ≈ ±1.5 п.п.).
- H2: отклонения на больших периодах (p = 8: 9.9 % vs 11.4 %) — малый n (213 строк), не структурный сдвиг.

**Recommendation:**
- Действие: оставить формулу как эталон; в отчётах помечать, что разница к теории — шум малых выборок на поздних периодах.
- Рычаг: `conversion ↑` (качество retention-модели).
- Сценарий проверки: до-после при смене `base_retention`/`decay` в `DataConfig`.
- Приоритет: L

### Finding 3: «Разрыв по когортам ×2.56» — артефакт окна наблюдения, не качество когорт

**Evidence:**
- Средняя `is_active` по когортам монотонно растёт 0.391 (2023-01) → 1.000 (2023-10) — **ровно** в порядке уменьшения числа наблюдённых периодов (10 → 1).
- Все когорты имеют одинаковую формулу удержания; различие создаёт period 0 = 100 % у молодых.

**Hypothesis:**
- H1: сегментный «разрыв» — Simpson-подобный артефакт состава (разное окно наблюдения), не разница в удержании.
- H2: реальный сигнал по когортам мог бы проявиться в `ltv_at_k(3)` — но там разброс узкий (23.2 … 25.4). `[❓ требует валидации]`

**Recommendation:**
- Действие: в BI/README запретить сравнение когорт по сырой средней `is_active`; использовать матрицу по периодам или `ltv_at_k(k)`.
- Рычаг: `revenue ↑` (корректная кросс-когортная оценка).
- Сценарий проверки: пересчёт дашборда Tableau с фильтром «observed periods ≥ k».
- Приоритет: M

### Finding 4: README занижает число тестов (34 vs фактических 39)

**Evidence:**
- `uv run pytest --collect-only -q` → **39 tests collected**; по файлам: `test_real_data.py` 16, `test_cohort_analysis.py` 14, `test_tableau_export.py` 9.
- README (строки 5, 38, 154) заявляет **34 = 12 + 13 + 9**; при этом строка 142 того же README говорит «`test_real_data.py` (16 тестов)».

**Hypothesis:**
- H1: README не обновлён после добавления тестов (реальные 16/14/9); внутренне противоречив (12 vs 16 для real_data).
- H2: часть тестов не собирается в CI-конфиге — опровергается локальным collect (39).

**Recommendation:**
- Действие: обновить README: «39 тестов (16 `real_data` + 14 `cohort_analysis` + 9 `tableau_export`)» в трёх местах (строки 5, 38, 154) и убрать дубль «12».
- Рычаг: `time_to_convert ↓` (доверие к документации).
- Сценарий проверки: `uv run pytest` → 39 passed, сверить с README.
- Приоритет: M

## Что не вошло

- **Реальные данные:** весь анализ — на синтетике; поведение реальных когорт (сезонность, промо, churn-драйверы) не проверялось. `real_data.load_real_data()` покрыт тестами, но на реальном CSV не прогонялся.
- **Границы генератора:** не проверялось, воспроизводится ли CSV на другой версии numpy/pandas (побитовое совпадение подтверждено только в текущем окружении).
- **Tableau-выгрузка:** `tableau/cohort_export.csv` и `.hyper` — производные артефакты; сверка выгрузки с `build_export_frame()` не выполнялась (по контракту — вне scope).
- **Причинность:** синтетика задана формулой, поэтому «эффекты» когорт не имеют бизнес-причины; выводы о мире из этих данных невозможны.
- **Статистическая мощность:** на поздних периодах (p ≥ 8) n ≤ 213 — отклонения от формулы в пределах шума, формальный тест не проводился.
- **Тесты:** число тестов сверено (39), но сами тесты на предмет покрытия ветвлений не ревьюились.
