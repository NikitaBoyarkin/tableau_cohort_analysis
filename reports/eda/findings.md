## Датасет вкратце

`cohort_data.csv` содержит 5 469 строк, одна строка = **пользователь × месяц наблюдения**
(`user_id` × `period`). Период прихода когорт: 2023-01 … 2023-10 (10 когорт), горизонт
наблюдения 0 … 9 периодов. Качество данных — **хорошее**: 0 пропусков, 0 дубликатов,
контракт из 6 колонок соблюдён (10/10 проверок валидности PASS), `seed=42` воспроизводит
CSV побитово.

## Топ проблем качества

### Проблема 1: README занижает число тестов — 34 против фактических 39
- **Что:** README (строки 5, 38, 154) заявляет «34 теста (12 `real_data` + 13 `cohort_analysis` + 9 `tableau_export`)». Фактически `pytest --collect-only` собирает **39**: 16 + 14 + 9. Строка 142 того же README уже говорит «16 тестов» для `real_data` — документ внутренне противоречив.
- **Влияние:** подрывает доверие к документации и к «правдивости» README-метрик; цифра проверяется одной командой.
- **Действие:** обновить три места в README до 39 (16 + 14 + 9), убрать противоречие «12 vs 16».
- **Владелец:** аналитик / автор проекта.

### Проблема 2: «Разрыв по когортам ×2.56» может быть прочитан как разница в качестве когорт
- **Что:** средняя `is_active` по `cohort_month` монотонно растёт 0.391 → 1.000 — ровно в порядке уменьшения окна наблюдения (10 → 1 период). Младшие когорты содержат только period 0 (100 % по конвенции).
- **Влияние:** сравнение когорт по сырой средней даёт ложный «тренд качества притока»; в BI/Tableau это типовой источник неверных выводов.
- **Действие:** запретить сравнение по сырой средней; использовать матрицу «когорта × период» или `ltv_at_k(k)` с фиксированным горизонтом. Принять как известное свойство треугольного окна.
- **Владелец:** аналитик.

### Проблема 3: Ложная «аномалия» в недельной динамике (2023-08-13)
- **Что:** профилировщик по `join_date` (всегда 1-е число месяца) строит недельную ось с нулями в не-первых неделях и флагует скачок −100 %.
- **Влияние:** артефакт оси, а не сбой данных; при автоматической интерпретации может читаться как инцидент.
- **Действие:** не использовать `join_date` как недельную ось; правильная ось — `cohort_month` (поток) и `period` (поведение). Принять риск (порог флага не настроен под месячную ось).
- **Владелец:** аналитик.

## Что в порядке

- 0 пропусков и 0 полных дубликатов; дубликатов ключа `(user_id, period)` нет.
- Все числовые колонки целочисленные и в валидных диапазонах; `is_active ∈ {0,1}`, `period ≥ 0`, `revenue ≥ 0`.
- `cohort_month` корректно выводится из `join_date`; `join_date` всегда 1-е число месяца; ровно одна строка `period == 0` на пользователя.
- `seed=42` воспроизводит CSV побитово (`DataFrame.equals == True`).
- Blended-кривая удержания совпадает с формулой `0.85 · 0.75^(p-1)` (max |Δ| = 0.0149; R² = 0.9945).
- `revenue` активных месяцев центрируется на λ = 10 (mean 9.97, median 10) и плоская по тенуре.
- `ltv_at_k(3)` даёт узкий сопоставимый разброс 23.2 … 25.4 (8 определённых когорт).
